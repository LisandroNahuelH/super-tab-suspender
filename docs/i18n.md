# Internationalization

The extension ships its UI in the browser's language. This page explains where the copy lives, which checks guard it, and how to add a language.

## Where the copy lives

| Artifact | Role |
|---|---|
| `public/_locales/<locale>/messages.json` | The runtime catalogs loaded by Chrome, one folder per language |
| `public/_locales/en/messages.json` | The canonical catalog: every other locale mirrors its keys |
| `docs/i18n/chrome-web-store-locales.json` | Locale registry: runtime folder, text direction, and the status of each language for the runtime, the store listing and QA |
| `public/manifest.json` | Declares `default_locale` and uses `__MSG_...__` placeholders for the extension name and description |

The registry is data for the tooling, not documentation: it is the single place that records which languages are live, pending, or alias-only (for example, regional English variants that reuse the English folder).

## The audit chain

Four audits run on every build, in this order, and again in CI through `npm run verify`:

| Script | What it enforces |
|---|---|
| `tools/i18n/check-i18n.mjs` | Every locale has exactly the keys of the canonical catalog, none empty |
| `tools/i18n/audit-title-case.mjs` | The extension name follows the project's title-case rules in every locale |
| `tools/i18n/audit-translations.mjs` | No non-English value is left identical to English unless it is in the intentional allow-list (units and the brand link label) |
| `tools/i18n/audit-literals.mjs` | No visible copy is hardcoded in the popup and restore-page sources; it must come from a catalog |

Supporting tools:

| Script | Use |
|---|---|
| `tools/i18n/bootstrap-all-locales.mjs` | Creates any missing locale folder from the registry and the canonical catalog |
| `tools/i18n/fix-brand-name.mjs` | Rewrites the brand string in every catalog after a naming change |
| `tools/i18n/manifest-store-copy.mjs` | Renders the store listing copy for each language from the catalogs |
| `tools/i18n/sync-manifest-store-copy.mjs` | Pushes that copy into the store-listing pipeline |
| `tools/i18n/capitalize-word-initials.mjs` | Helper used by the title-case audit |

Run the whole gate with:

```bash
npm run verify
```

## Adding a language

1. Add the locale to `docs/i18n/chrome-web-store-locales.json` with its runtime folder, text direction and status.
2. Create the catalog: `npm run i18n:bootstrap`.
3. Translate the `message` values only. Never translate keys, and never add or drop keys.
4. Keep placeholders (`$PLACEHOLDER$`) intact and in the same order.
5. Leave a value identical to English only when it is intentional (units, brand strings) and add it to the allow-list in `tools/i18n/audit-translations.mjs` with a comment saying why.
6. Run `npm run verify` and fix whatever the audits report.

## Rules that keep the catalogs consistent

- Edit `en` first: it is the source of truth for keys.
- One product term per concept, translated the same way everywhere: *suspend*, *restore*, *auto-suspension*, *suspended tab*, *pinned*. Keep the brand name untranslated.
- No visible text in TypeScript or HTML. The literal audit fails the build when it finds some.
- Do not rename the extension in a catalog: the name is a brand asset, audited separately.
- The store listing has its own copy, its own character limits, and its own pipeline; it is not the runtime catalog.
